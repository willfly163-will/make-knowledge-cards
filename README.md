# make-knowledge-cards

把一篇文章拆成 5–8 张知识卡片：挑出真正重要的知识点，一张卡只讲一个，不编造原文没有的信息，信息不足时不凑数量。

## 1. 解决什么问题

读完一篇长文，一周后能回忆起来的内容往往只剩标题。把原文存进笔记软件不等于消化了它，因为原文不能被打乱顺序单独使用，也没法直接拿去做复习。

直接做摘要解决不了这个问题：摘要按原文顺序走，删掉上下文就读不懂，而且经常把三五条知识压成一段话，复习时还是要重读。

这个 Skill 处理的是中间那一层——**可独立阅读的最小知识单元**。每张卡自带标题、一句话结论、解释和例子（或自测题），可以打乱顺序看、可以单独发给别人、可以直接当复习材料。它不负责评价文章好坏，只负责把文章里站得住的知识点挖出来，并按固定格式摆好。

## 2. 主要功能

**抽取**：先通读，再按四条标准筛单元——承载主旨、可迁移、被作者强调、有纠偏价值，满足两条才保留。抽取粒度以"是否对应一个独立的判断或动作"为准，对策相同的合并，对策不同的才拆开。

**控量**：目标 5–8 张。合格单元不足 5 个，有几张交几张，并写明 `**取舍**：原文有效知识点不足，未凑数`；超过 8 个，按标准择优取 8 张，并说明哪些次要主题未成卡。

**去重**：同一知识点只保留信息量最大的那一次表述；一因多果、多因一果都合成一张卡；全文核心论点句写进元信息，不单独占一张卡。

**写卡**：固定四个字段，不增删。

| 字段 | 约束 |
| --- | --- |
| 标题 | 不超过 14 字，不带标点，不用副标题 |
| 核心知识 | 一句话，含标点 40 字以内，可判断真假的陈述句 |
| 简明解释 | 2–4 句，必须比核心知识多提供原因、条件、边界或后果 |
| 例子 | 原文例子，或"自测：问题 + 一句话答案"，二选一不并列 |

**防编造**：解释只重组原文信息；原文只有断言、推不出机制时，只做改写，说不出原因就把该单元并进相邻卡；没有成形例子时改出自我测试题，不自造例子；数字和专有名词照抄，不改写精度。

**输出**：先是元信息（来源 / 卡片数 / 覆盖 / 可选取舍），再是卡片正文；不写评价和推荐语。可按要求存成 Markdown 文件。

**输入与边界**：

| 输入 | 支持 |
| --- | --- |
| 对话里直接粘贴的文章正文 | ✅ |
| 本地 `.md` / `.txt` 文件路径 | ✅ |
| 网页链接、需要抓取的页面 | ❌ 请复制正文 |
| PDF、Word、EPUB、图片 | ❌ 请另存为 `.md` / `.txt` |
| Anki / CSV / JSON 导出 | ❌ 只产出 Markdown |
| 图形界面、图片卡片 | ❌ 不提供 |

另有两项明确不做：不评价文章质量、不给写作建议；不补充原文之外的背景知识，也不做外部事实核查（仅当原文自相矛盾时提示一句）。

**拒答**：有效长度不足 300 字，或通篇是通知、日程、目录、清单、口号、个人情绪记录，或找不到任何可复述的结论与机制，就说明原因并停手，不产出卡片。

## 3. 安装方法

把 `skills/make-knowledge-cards` 整个目录复制到技能加载目录。二选一：

```bash
# 用户级：所有项目可用
cp -r skills/make-knowledge-cards ~/.workbuddy/skills/

# 项目级：仅当前项目可用
mkdir -p .workbuddy/skills && cp -r skills/make-knowledge-cards .workbuddy/skills/
```

**注意**：本仓库里的 `skills/` 目录不是技能加载路径，直接放在这里不会自动生效，必须复制到上面两处之一。

安装后目录结构：

```
make-knowledge-cards/
├── SKILL.md            # 全部规则：抽取判据、写卡模板、自检清单
└── agents/
    └── openai.yaml     # 适配层，指向 SKILL.md
```

**验证**：重启会话，输入"用 make-knowledge-cards 把下面这段拆成知识卡片"，跟一段 300 字以上的文章。能按四字段出卡即为生效。

**免安装**：把 `SKILL.md` 正文（去掉 frontmatter）粘到对话开头，再贴文章，效果相同。

## 4. 使用方法

触发语句，任选其一：

```
把这篇做成知识卡片：<粘贴正文>

用 make-knowledge-cards 处理 notes/某篇文章.md

把这篇拆成几张卡，重点保留机制，不要摘要
```

几点实际行为：

- **多篇一起给**：会逐篇处理，每篇用一个二级标题隔开。
- **存文件**：要求保存时，写到原文件同目录的 `<原文件名去扩展名>-cards.md`（`.txt` 输入也输出 `.md`）；原文来自粘贴且没指定路径时，会先问存到哪里。
- **会被拒的情况**：通知、日程、清单、短讯，或没有结论与机制的文字。这时不会硬产出卡片。
- **不想要的输出**：不允许 Anki、CSV、JSON 或图片卡片。需要结构化复习材料，得另做转换。

## 5. 输入输出示例

输入（原文节选，完整文章约 900 字）：

> 做订阅制的人，第一反应往往是"定低一点，先把用户量做起来"。这个直觉在一次性买卖里成立，在订阅制里是错的。
>
> 所以第一个错误，就是用一次性交易的定价逻辑去做订阅。订阅的收入结构是"用户数 × 月度价格 × 留存月数"，三个乘数里，价格是最容易被低估的一个。把月费从 29 压到 19，用户不会因此多留一年；但每个付费月都少 34% 的收入，而获客成本一分没降。
>
> 第二个错误，是把免费额度和低价档当成同一件事。免费额度是让人验证价值，低价档是让人付钱。两者的区别在于：免费额度不需要用户做任何决策，低价档要求用户绑定支付方式。

输出（节选，完整运行产出 4 张卡）：

```markdown
**来源**：订阅制定价最常见的三个错误｜约 900 字
**卡片数**：4 张
**覆盖**：订阅不是流量生意而是留存生意；定价不能用一次性买卖的直觉，它是商业模型的一部分。
**取舍**：原文有效知识点不足，未凑数

---

### 卡片 1｜降价逻辑在订阅制失效

**核心知识**：订阅制照搬一次性买卖的降价逻辑，收入下降且回本周期拉长，可能拖垮现金流。
**简明解释**：订阅的收入结构是"用户数 × 月度价格 × 留存月数"，价格是最容易被低估的乘数。降价不会让用户多留，获客成本一分不降，每个付费月却直接少收；毛利要靠时间摊薄获客成本，定价过低拉长回本周期，很多产品死于回本周期超出现金流能撑的时间，而不是没人用。
**例子**：原文例——把月费从 29 压到 19，用户不会因此多留一年，但每个付费月少 34% 的收入，而获客成本一分没降。

### 卡片 2｜免费额度不是低价档

**核心知识**：免费额度用于验证价值，低价档用于收钱，二者不是同一件事。
**简明解释**：免费额度不需要用户做任何决策，低价档要求用户绑定支付方式。低价档定得过便宜，用户会把它当成"免费额度的延长"，既没有升级动力，也没有认真使用的动力，只是花很少的钱买一个"以后再说"的选项。
**例子**：自测：健康的定价里，最低付费档应该解决什么问题？答案：解决一个完整的小问题，而不是解决半个问题。
```

两个值得注意的地方：

- 只有 4 张卡，因为原文真正能独立成卡的知识点不足 5 个。规则不允许为凑数拆分，所以写了 `**取舍**` 行。
- 卡片 2 的"例子"是自测题而不是例子，因为原文没有给出成形的例子。规则不允许自造例子。

## 设计取舍

**为什么不直接做摘要**：摘要按原文顺序走，卡片按知识点走。卡片要能被打乱顺序单独阅读，所以强制每个单元自足、不出现"如上所述"。

**为什么上限是 8 张**：超过 8 张，复习成本超过重读原文，卡片就失去意义。

**为什么允许少于 5 张**：强行凑数会产出"背景介绍""重要概念"这类空卡，违反"一张卡一个知识点"的前提。宁可少，不可注水。

**为什么把判据写成动作**：早期版本用"解释要讲清机制""撑不起两句就并卡"这类模糊阈值，实测中不同执行者会做出 7 张或 12 张、4 张或 5 张的不同结果。改成"是否对应独立动作""能否说出核心知识之外的原因或条件"之后，判断不再依赖计数。

## 已知限制

- 抽取粒度仍依赖对"一个知识点"的判断，弱论证文章（观点多、机制少）的卡数会在 4–5 张之间浮动，这是原文信息量问题，不是规则问题。
- 自测题的答案常常接近解释的复述，读起来有重复感。
- 不做外部事实核查，原文自身的事实错误不会被发现。
- 中英混排的技术文章，术语保留原文词，中文解释可能出现译名不统一。

## 测试记录

三个测试用例、三轮执行，详见 `tests/RESULTS.md`。可复述的结论：模糊阈值会让不同执行者产出分叉，判据必须写成可验证的条件。
