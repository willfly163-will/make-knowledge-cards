# Make Knowledge Cards

## 用途

把一篇有信息密度的文章压缩成 5–8 张可独立阅读、可复习的知识卡片。

目标不是缩写全文，而是挑出真正能留下来的知识单元：只用这几张卡，读者应当能复述文章的主干。

## 输入范围

支持的输入：

- 用户在对话中直接粘贴的文章正文
- 用户给出的本地 `.md` / `.txt` 文件路径

一次只处理一篇。用户给多篇时逐篇处理，每篇用一个二级标题（`## <文件名或标题>`）隔开。

不支持的输入，直接说明限制，不尝试绕过：

| 输入类型 | 处理方式 |
| --- | --- |
| 网页链接、需要抓取的页面 | 说明不支持，请用户复制正文粘贴进来 |
| PDF、Word、EPUB、图片 | 说明不支持，请用户另存为 `.md` / `.txt` 或粘贴文本 |
| Anki 导出、CSV/JSON 卡片格式 | 说明不支持结构化导出，只产出 Markdown |
| 图形界面、可视化卡片 | 说明不提供 |

不要为绕过限制临时写解析脚本。遇到不支持的类型，一句话说明 + 给可行替代方案，然后停止。

## 工作流

### 第一步：读取与可行性判断

1. 粘贴文本：直接使用，不要求用户补充来源。
2. 文件路径：读取整个文件；文件不存在或编码异常时如实报告，不要猜测内容。
3. 统计有效长度：按非空白字符计（不含 Markdown 符号与换行）。
4. 判断是否值得拆卡。出现下列任一情况，**不产出卡片**：
   - 有效长度少于 300 字；
   - 通篇是通知、日程、目录、清单、口号、个人情绪记录；
   - 找不到任何"可复述的结论或机制"。

   此时直接回复 2–3 句：说明为什么拆卡会变成注水，以及需要什么样的文字才能处理。这种回复**不给元信息块、不给卡片、不加分隔线**，形态与正常输出明确区分。

### 第二步：抽取知识单元（此时不写卡片）

先通读，列候选单元。每个单元必须满足下面四条中至少两条才保留：

1. **承载主旨**：处于论点、机制、因果链或方法的关键位置，删掉后主线断裂。
2. **可迁移**：脱离本文语境仍能用在别处，不是只在这篇文章里成立的细节。
3. **被作者强调**：通过定义句、转折、重复、数据、总结句被突出。
4. **有纠偏价值**：反直觉、纠正常见误解、或给出量化边界。

**抽取粒度（关键）**：一个单元 = 一条能独立成句、独立回答一个"为什么"或"怎么做"的结论。判定方法：

- 能用一句"因为 A，所以 B"或"要 X，就得 Y"独立说清 → 是一个单元。
- 必须连着下一个单元才成立 → 本来就是一张卡，合并。
- 两个单元各自能独立回答一个不同的问题 → 两张卡。

**更硬的判据：一个单元是否对应一个独立的判断或动作。** 如果两张卡的对策是同一件事（例如"留出空闲容量"与"盘越满越差"其实是同一条建议），它们就是一张卡；如果两张卡各自指向不同的检查项或动作（例如"少写满"与"检查 Trim 开关"），才拆开。仅在解释里互相引用的相邻单元（例如垃圾回收与 Trim），按此判据判断，不按段落在哪就怎么切。

**一因多果、多因一果都算一张卡**（用分号并列后果或原因），不要按"几个后果就几张卡"切。同一知识点的正反两面也只算一张。

明确排除：背景铺垫、行业概况、寒暄式开场、作者个人经历、情绪表达、过渡句、只在原文成立的参数与日期、重复表述（同一知识点只留信息量最大的那一次说法）。

全文的核心论点句如果与某张卡高度重合，**写进元信息的"覆盖"行**，不单独成卡。

### 第三步：排序与定数量

- 有依赖关系时按依赖排，先概念后推论；单元之间并列时保持原文顺序。不要为了显得有结构而打乱并列项。
- 目标 5–8 张，不是必须 8 张。
- 合格单元少于 5 个：有几张交几张（2–4 张都正常），加一行 `**取舍**：原文有效知识点不足，未凑数`。
- 合格单元多于 8 个：按第二步四条标准择优取 8 张，加一行 `**取舍**：另有 X 个次要主题未成卡`，能一句话概括就列出主题，不能概括就保留这半句。

### 第四步：写卡片

每张卡严格使用下面的结构，不增删字段：

```
### 卡片 1｜标题
**核心知识**：一句话，含标点 40 字以内，可判断真假的陈述句
**简明解释**：2–4 句，讲清为什么或怎么运作
**例子**：原文例，或"自测：问题 + 一句话答案"
```

写作规则：

- **一卡一点**：解释里若出现"另外""其次""同时也"引出独立结论，拆成两张。
- **解释只重组原文信息**：可改写、可压缩；允许补的连接词仅限原文相邻句之间已隐含的因果或条件关系，不允许新增中间环节、机制或限定条件。
- **原文没给机制就不硬造**：源文只是一句断言、推不出"为什么"时，简明解释只做改写与同义展开。**检验方式不是数句子，而是看能不能说出核心知识之外的原因、条件、边界或后果**；说不出，说明这个单元信息量不足，并进相关的卡，不要单独成卡。
- **解释必须比核心知识更进一步**：简明解释不得复述核心知识，也不得把核心知识换词重写。出现"核心知识 = 解释第一句"的情况，直接并卡。
- **例子二选一，不并列**：优先用原文例子并标"原文例"；原文有数据或结论但没有成形例子时，写自测题（不要自造例子）。确需构造示意例子时标"示意（非原文）"，且不得包含对真实世界的具体断言（不带数字、不带具体公司或人物）。
- **自测答案只能落在本卡内**：答案不得依赖其他卡片的内容，也不得依赖原文之外的知识。
- **数字与术语照抄**：精度、限定条件、专有名词不改写。原文说"约 30%"，不写成"30%"。
- **标题**：不超过 14 字，不带标点，不用副标题。"重要概念""核心思想""背景介绍"这类空标题不合格。
- **卡片自足**：不出现"如上所述""文中提到""前面那张卡"。
- **语言**：跟随原文语言；中英混排时解释用中文，术语保留原词并在首次出现时给白话注解。

## 输出格式

先给元信息，再给卡片正文。元信息固定 3 行，需要说明取舍时加第 4 行：

```
**来源**：标题（无标题时用文件名）｜约 N 字
**卡片数**：N 张
**覆盖**：一句话说明这几张卡的主线，可包含全文论点句
**取舍**：（只在不足 5 张或超过 8 张时出现，一句话）

---

### 卡片 1｜…
```

- N 字按非空白字符计，取整到百位。
- 元信息与正文之间用一条 `---` 分隔；正文内部不再用分隔线。
- 不写评价、不写推荐语、不写"希望对你有帮助"。
- 默认在对话里直接输出 Markdown。
- 用户要求存文件时，写到原文件同目录的 `<原文件名去扩展名>-cards.md`（`.txt` 输入也输出 `.md`）；原文件来自粘贴且用户未指定路径时，先问一句存到哪里。

## 交付前自检

逐条过一遍，任一条不通过就先改再交：

1. 每张卡的"核心知识"是不是只有一句话、40 字以内？两句话就拆卡。
2. 有没有哪张卡的"简明解释"只是在复述"核心知识"？有则并卡。
3. 任意两张卡之间的信息重合是否超过 50%？是则合并。
4. 解释和例子里有没有原文不存在的数字、案例、机制、断言？有则删。
5. 每张卡是否都有"例子"或"自测"字段，且只写了一种？自测答案能否只靠本卡推出？
6. 标题是否具体、不带标点、不超过 14 字？
7. 数量是否在 5–8？不在范围内时是否已写 `**取舍**` 行说明原因？
8. 把卡片单独发给没见过原文的人，能否读懂？出现"上文""文中"就改。
9. 元信息是否 3 行（必要时 4 行）？是否混入了评价性语句？

## 已知失败模式

| 现象 | 根因 | 修正 |
| --- | --- | --- |
| 卡片读起来像分段摘要 | 按原文段落切，而非按知识点切 | 回到第二步重新抽取单元，合并跨段落讲同一件事的部分 |
| 一张卡里塞了三层因果 | 抽取粒度过粗 | 以"一条可独立陈述的结论"为粒度重切 |
| 一张卡被拆成好几张 | 按"后果个数"切卡 | 一因多果合成一张，用分号并列 |
| 解释里冒出原文没有的机制 | 用自身知识填空 | 删掉该句；说不出原因或条件就并卡 |
| 解释复述核心知识 | 该单元信息量不足 | 并进相邻卡，或补上原文给出的原因与边界 |
| 例子变成第二个知识点 | 举例时引入新概念 | 例子只复现本卡结论，不携带新信息 |
| 强凑到 8 张 | 把数量当指标 | 少于 5 个合格单元就交 3–4 张，并写 `**取舍**` |
| 自测题的答案卡里没有 | 题目从外部知识出 | 题目只能指向本卡内容，答案在卡内可查 |
| 全文结论句消失 | 与某张卡重复被当冗余删掉 | 结论句写进元信息"覆盖"行 |

## 不做的事

- 不评价文章质量、不给写作改进建议（用户另行要求时按用户要求执行，优先级高于本条）。
- 不补充原文之外的背景知识，也不做外部事实核查；只在原文自相矛盾时（例如前后数字不一致）于末尾单列一行提示，不改写卡片内容。
- 不输出 Anki、CSV、JSON 等结构化导出。
- 不生成图片卡片或界面。
- 不在用户没有要求时创建额外文件。

## 示例

输入（片段）：

> 番茄工作法的核心不是 25 分钟，而是"不可中断的最小承诺"。25 分钟只是一个默认值，它的作用是短到让人愿意开始、长到足以进入状态。真正让方法生效的是中断处理规则：中断出现时，不立刻响应，先记在一张纸上，等这个番茄结束再处理。多数人失败的原因是中途切走，而不是时长选错。

输出（仅示例 1 张卡，实际输出不含代码围栏）：

```markdown
### 卡片 1｜不可中断比时长更关键

**核心知识**：番茄工作法生效靠时段内不切换任务，而非 25 分钟这个时长。
**简明解释**：25 分钟是可调默认值，作用是短到容易启动、长到能进入状态。方法真正的机制是中断处理：中断发生时先记录在纸上，等当前时段结束再处理，从而避免切走。
**例子**：原文例——被打断时把事写在纸上，番茄结束后统一处理；文章指出多数人失败在于中途切走，而非时长选错。
```
